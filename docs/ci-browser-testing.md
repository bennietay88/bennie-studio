# CI browser testing

Verification must pass before browser tests start. The existing `browser-e2e` check aggregates all selected shard results. Only explicitly reviewed portfolio and public marketing paths receive a reduced browser suite; mixed, unknown, infrastructure, billing, permission and database changes receive the full suite. Documentation-only changes skip app testing. Manual and nightly runs (02:00 Malaysia time) run the complete desktop/mobile Chromium suite. A single fixture build is uploaded as a one-day private Actions artifact and reused by each shard. Browser binaries are cached by OS, architecture and dependency lockfile; required system packages are still installed. The four full-regression shards and three targeted shards run in parallel, which may increase total runner minutes while reducing wall-clock time. Typecheck, unit/domain tests, vulnerability audit and SQL isolation checks are not weakened. If classification is uncertain, test the full suite. Do not change required checks or bypass failures.
